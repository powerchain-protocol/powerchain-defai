# PowerChain DeFAI Postman Datasets

These files provide source-controlled, non-secret test data for Postman datasets and data-driven collection runs. PowerChain standardizes source-controlled Postman iteration data on CSV. See <https://learning.postman.com/docs/tests-and-scripts/datasets/create-datasets>.

## Data sources

| File | Use |
| --- | --- |
| `PowerChain-DeFAI.dataset.csv` | Portable iteration-data source for collection runs |

The CSV file is generated by `pnpm postman:datasets:generate` and its exact contents are validated by `pnpm postman:datasets:check`.

## Import and use

1. Import the generated collection and the local or production environment from `api/postman/`.
2. Create or select a Postman dataset.
3. Add `PowerChain-DeFAI.dataset.csv` as the data source.
4. Use the dataset as iteration data for the collection or a method folder such as `GET` or `POST`.
5. Keep credentials in the selected environment or Postman Vault rather than in dataset rows.

Iteration-data variable names intentionally match collection variables such as `baseUrl`, `swapUrl`, `bridgeUrl`, `id`, `transferId`, swap inputs, and Bridge inputs.

## Safety

- `apiKey` is intentionally blank in source-controlled rows.
- Never store wallet seed phrases, private keys, treasury keys, provider API secrets, signed production transactions, or customer secrets in these files.
- Swap and Bridge rows are templates, not execution evidence.
- A Postman response does not prove wallet approval, chain finality, or Wormhole NTT settlement.
- Review every mutation request before sending it against production.

Regenerate and verify with pnpm only:

```bash
pnpm postman:datasets:generate
pnpm postman:datasets:check
pnpm postman:generate
pnpm postman:check
```
